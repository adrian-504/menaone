# Architecture decisions required

These questions **must be answered by the owner before cloud or multi-user implementation**. They are deliberately **not answered here**. Each entry lists what the answer changes and what is safe to do before it's answered.

| # | Question | What the answer changes | Safe to do before answering |
|---|---|---|---|
| Q1 | **Tenant model:** will MENA One only ever serve MENA BIG's own Microsoft tenant, or other organisations too? | Whether `tenant_id` is a constant or a partition key on every table; app registration (single- vs multi-tenant). | Record `tid` alongside user `oid`. |
| Q2 | **Online, offline or hybrid:** must a laptop work fully offline (travel, poor connectivity), read-only offline, or only online? | Whether a local replica and sync engine exist at all; conflict design; effort doubles for offline-write. | Identity, global IDs, version checks, personal/shared split. All are needed in every option (SYNC_READINESS). |
| Q3 | **Source of truth:** does the central store become authoritative for company data, with the local DB a cache/replica? Or does each desktop remain authoritative for some data (e.g. personal notes/tasks)? | Write path, backup strategy, what survives a lost laptop. | Classify each table as shared / personal / derived. |
| Q4 | **Hosting and data residency (PDPL):** where may client data live (in-Kingdom, GCC Azure region, EU)? Is an Azure subscription in the company tenant available? Who administers it? | Provider, region, cost, legal review. | Nothing server-side. |
| Q5 | **Data classification:** which data is personal (my tasks, my notes, my flagged mail, my calendar) vs team-visible (companies, contacts, proposals, agreements, opportunities, projects, meetings)? Are notes and tasks shareable? | Table split, authorisation rules, what syncs to whom. | Draft a table-by-table classification for owner review. |
| Q6 | **File architecture:** do client folders stay in one person's OneDrive (synced locally), move to a SharePoint/Teams document library, or both? Are references stored as relative paths or Graph drive-item IDs? | `microsoft_files`, `folder_path`, document paths, `localfiles.rs` vs Graph Files scopes, Windows OneDrive discovery. | Stop adding new absolute-path columns. |
| Q7 | **Graph ownership:** do Graph calls stay in each desktop app (delegated, per user), move to a backend (on-behalf-of / application permissions), or split (personal mail/calendar in the client, shared libraries in a backend)? | Token handling, consent, backend scope, security model. | Fix timeouts, token storage and calendar reconciliation (these apply either way). |
| Q8 | **Roles and permissions:** is "everyone sees everything" acceptable for 5–10 people, or are there restricted records (commercial terms, HR-related clients, finance)? | Authorisation layer complexity. | Add actor/owner as user IDs. |
| Q9 | **Audit requirements:** is the trigger-written local activity feed enough, or is a tamper-resistant audit log required (who changed a fee, who deleted an agreement)? | Server-side append-only log vs local table. | Record actor on activity. |
| Q10 | **Distribution and signing:** Apple Developer ID + notarisation? Windows code-signing certificate? Auto-updates? | Keychain ACL design (SECURITY_AUDIT S1), SmartScreen, update channel. | Nothing beyond evaluating cost. |
| Q11 | **Windows scope:** full parity, or a subset of modules for Windows colleagues initially? | UI adaptation effort, PowerPoint-for-Windows validation. | Run CI once on Windows. |
| Q12 | **Migration of existing data:** is today's single database the seed of the shared dataset? Who reviews ownership assignment for about 250 proposals, 106 agreements and 167 companies? | Identity back-fill, owner mapping, one-time cleanup. | Nothing irreversible. |
| Q13 | **Build vs buy for sync (only if Q2 = offline):** a custom sync layer, or an off-the-shelf SQLite↔Postgres sync product? | Server stack and cost. | Nothing. Premature until Q2, Q3 and Q5 are answered. |
